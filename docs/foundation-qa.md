# Separate foundational design challenge and acceptance

This challenge is separate from the implementation design. It records falsifying cases and the
owner that must reject them. It is not a declaration that every platform/experiment has passed.
The original reviewed design and negative controls N01–N22 remain the starting acceptance contract.

## Challenges resolved in the design

- Collapsing layers or adding a pipeline framework would erase real authority boundaries. Retain
  the manifest graph; reduce parallel plan/report coordination instead. Compiler include/link/AST
  checks remain independent of this design prose.
- A binary/continuous variant alone does not validate raw options, paths or a moved request. Keep
  before-I/O admission and readiness, and prove impossible binary photometric state at compile time.
- Marking G01 selectable would invent a command. The closed classification corrects documentation
  without extending runtime method discovery; unknown classifications/attributions must fail.
- A compiled counterexample accepted completed D01 after selected unstarted I01. The fixed-order
  observation validator now rejects later work after a selected incomplete predecessor.
- Merely collecting reports does not fix lifecycle truth. Earlier completed reports must survive,
  untouched selected stages must be exactly initial facts, and success requires completion. A
  `noexcept` accessor cannot use potentially throwing visitation; the exception contract is explicit.
- Restoration reports contain allocated PSF vectors/paths. Borrow during serialization and move
  the terminal aggregate after commit; do not copy it to preserve known effects.
- The existing exact A–F contract already solves current geometry. Asymmetric mirror/turn/mask/DPI
  cases are stronger evidence than another wrapper or symmetric fixture.
- Charged peak accounting is a ledger observation, not RSS. Measure real child CPU/RSS independently;
  sampled thread/disk peaks and unavailable native-call timing must remain qualified.
- Intel LLVM caches must not cross host OS identities; source tools bind host version and the
  deployment floor, compile for that floor and use separate runner-OS CI cache keys.
- A deployment flag can pass on a newer OS. Check physical macOS major and CPU, then execute the
  relocated package on both minimum lanes, with complete latest-attempt CI reconciliation.
- Recorded artifacts agreeing cannot prove a given binary produced them. Quality evaluation must
  actually replay frozen candidate and comparator settings and compare results as well as independently checking integers.
- Evaluation report creation is exclusive: an existing source or prior report must survive collision.
- Positive mean scores can conceal faint-mark loss. Any harm blocks the class; missing/uncertain
  human evidence abstains. An institutional rights label is evidence to review, not a warranty.

## Execution evidence and limits

The unchanged baseline `09e7a97` passed `python tools/check_all.py` on the local ARM64 macOS host,
including all 343 tooling cases and the complete Docker Linux ARM64 release workflow. Baseline
remote direct quality run 38130577775 and nightly run 38130830502 are evidence for that commit only.
The handoff archive passed its confined-path, closed-inventory and digest validator; its SHA-256 is
`61d92cfaf3d53f451906f692745d3b416aead73bdffeb5b4b254905872fe4b78`.

Implementation acceptance must retain fresh command logs, discovered/executed test identities,
compiler/OS/input facts, exact commit/run/attempt IDs and artifacts. Local macOS 27 execution is
forward-host evidence, not macOS 15 proof. Missing human reviewers block measured field-quality
claims. A PR, workflow definition, synthetic score fixture or successful handoff hash does not
establish final program acceptance. Final delivered evidence must supersede this baseline explicitly.
